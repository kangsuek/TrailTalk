# TrailTalk 구현 계획서

기준 문서: [TrailTalk_요구사항_설계서.md](TrailTalk_요구사항_설계서.md) (이하 "설계서")

## 1. 목적과 전제

설계서의 5단계 개발 방법을 실제 작업 단위로 나누고, 단계마다 무엇을 만들고, 어떤 요구사항(FR/NFR)을 채우며, 어떻게 완료를 확인하는지 정한다. 작업 ID(예: `S1-03`)는 Claude Code에 "S1-03 구현"처럼 요청하는 단위로 쓴다.

**현재 상태 (2026-10-12)**

| 항목 | 상태 | 조치 |
|---|---|---|
| 저장소 | `docs/` 외 코드 없음, git 미초기화 | 0단계에서 `git init`과 골격 생성 |
| Python | 시스템 3.9.6 | 설계서 기준 3.12 필요 → `uv`로 3.12 가상환경 구성 |
| Node | v24 설치됨 | 웹 앱에 그대로 사용 |
| Claude Code CLI | 설치됨(`~/.local/bin/claude`) | 버전 고정, `claude setup-token`으로 서버용 토큰 발급 |
| ffmpeg | 미확인 | 서버 오디오 변환(Opus 디코딩, MP3 처리)에 필요 → 설치 확인 |

**전체 일정 (약 10~13주)**

| 단계 | 기간 | 산출물 | 핵심 완료 기준 |
|---|---|---|---|
| 0. 준비·기술 검증 | 3~5일 | 저장소 골격, Claude CLI 검증 결과 | CLI 상주 프로세스로 스트리밍·인터럽트·MCP 도구 호출 확인 |
| 1. 제니 텍스트 대화 | 1~2주 | 서버 대화 API, 페르소나, 웹 텍스트 대화 화면 | NFR-07 통과, 첫 문장 2초 이내 |
| 2. 대화 기록 | 1~2주 | 턴 저장, 일지 추출, 기억 블록, 일지 화면 | 대화 5회가 일지로 정리, 지난 아이디어 언급 |
| 3. 웹 음성 대화 | 2~3주 | VAD·STT·TTS·끼어들기·오프라인 큐, `client-contract.md` | 실제 산책 1회 완주, NFR-01·NFR-03 측정 |
| 4. 안드로이드 포팅 | 3주 | Kotlin 앱 | 화면 조작 0회 등산 완주, 배터리 10% 이내 |
| 5. 다듬기·확장 | 2주 | 설정·검색·내보내기·브리핑·일지 MCP | P2 기능 동작 |

## 2. 0단계 — 준비와 기술 검증 (3~5일)

가장 불확실한 부분은 Claude CLI를 서버의 상주 대화 엔진으로 쓰는 방식(설계서 4.9)이다. 1단계 설계가 여기에 기대므로 먼저 작은 실험으로 확인한다.

| ID | 작업 | 산출물 |
|---|---|---|
| S0-01 | `git init`, 설계서 5장의 폴더 구조 생성, `.gitignore`, `CLAUDE.md` 초안(폴더 구조·API 표·페르소나 분리 원칙·테스트 명령) | 저장소 골격 |
| S0-02 | `uv`로 Python 3.12 + FastAPI + SQLAlchemy + pytest 환경, `ruff` 설정 | `server/pyproject.toml` |
| S0-03 | Vite + React + TypeScript 웹 프로젝트, Vitest, oxlint | `web/package.json` |
| S0-04 | **CLI 검증 스파이크**: 아래 체크리스트를 스크립트로 확인하고 결과를 `docs/spikes/claude-cli.md`에 기록 | 검증 보고서 + 녹화한 stream-json 샘플 |
| S0-05 | 서버용 토큰 발급(`claude setup-token`), `.env`에 `CLAUDE_CODE_OAUTH_TOKEN`, 비밀값 관리 방식 결정 | `.env.example` |

**S0-04 검증 체크리스트**

- [ ] `--input-format stream-json --output-format stream-json --include-partial-messages`로 프로세스 1개에 여러 턴을 보내고, 토큰 단위 부분 출력이 오는지
- [ ] 생성 도중 인터럽트를 보내는 방법(stdin 제어 메시지 또는 시그널)과, 중단 후 같은 프로세스로 다음 턴이 이어지는지
- [ ] `--system-prompt`, `--model sonnet/haiku`, `--mcp-config` + `--allowedTools "mcp__trailtalk__*"`, `--disallowedTools` 조합이 의도대로 동작하는지
- [ ] 빈 작업 폴더에서 실행했을 때 사용자 설정·CLAUDE.md가 섞이지 않는지(`--setting-sources` 등 격리 옵션 확인)
- [ ] 프로세스 종료 후 `session_id`로 `--resume`하면 맥락이 이어지는지
- [ ] 첫 토큰까지의 지연(콜드 스타트 vs 상주 프로세스) 측정
- [ ] 출력 이벤트 샘플을 파일로 녹화(이후 테스트의 가짜 CLI 입력으로 사용)

검증 결과 인터럽트나 상주 프로세스가 불안정하면, 턴마다 `claude -p --resume <session_id>`를 새로 띄우는 방식으로 대체하고 지연 증가분을 1단계 완료 기준에 반영한다.

## 3. 1단계 — 제니 텍스트 대화 (1~2주)

대상 요구사항: FR-07, FR-08, FR-09, FR-10(일부), NFR-06, NFR-07, NFR-08

| ID | 작업 | 위치 |
|---|---|---|
| S1-01 | FastAPI 앱 골격, 설정 로딩(pydantic-settings), 헬스체크, 오류 응답 형식 | `server/app/` |
| S1-02 | SQLite + SQLAlchemy 모델과 마이그레이션(Alembic): `conversation_session`, `turn`, `note`, `user_profile`, `persona` (설계서 4.5) | `server/app/db/` |
| S1-03 | `LlmBackend` 인터페이스와 `ClaudeCliBackend`: 세션별 상주 프로세스 생성·종료, stream-json 파서, 부분 출력 이터레이터, 인터럽트, `--resume` 복구, 유휴 프로세스 정리 | `server/app/llm/` |
| S1-04 | 가짜 CLI 실행 파일(S0-04 녹화 출력 재생)과 파서 단위 테스트 | `server/tests/fakes/` |
| S1-05 | `personas/jenny.yaml` 스키마 검증 + 프롬프트 조립기(페르소나 → 상황 → 기억 → 역할 규칙, 페르소나 블록 맨 앞 고정). 기억 블록은 이 단계에서 빈 값 | `server/app/persona/` |
| S1-06 | 제니 도구 MCP 서버: `save_note`, `search_notes`, `summarize_session`, `pause_session`, `end_session`. 도구 호출 결과를 서버 이벤트로 전달 | `server/app/mcp/` |
| S1-07 | 문장 분할기(한국어 종결 어미·문장부호 기준, 스트리밍 입력 대응) | `server/app/voice/sentences.py` |
| S1-08 | API: `POST /sessions`(인사말), `POST /sessions/{id}/turns`(텍스트 입력, SSE 응답), `POST /sessions/{id}/end`(요약은 2단계), `GET/PUT /profile` | `server/app/api/` |
| S1-09 | SSE 이벤트 스키마 초안: `sentence`, `tool`, `done`, `error` (이 단계는 텍스트만) | `server/app/api/events.py` |
| S1-10 | 웹: 대화 화면(텍스트 입력, 문장 단위로 말풍선 채우기), `fetch` + 스트림 파서로 SSE 수신(POST라 `EventSource` 대신), OpenAPI 타입 생성 스크립트 | `web/src/` |
| S1-11 | 페르소나 톤 평가 스크립트: 고정 질문 20개 → 답변 → `claude -p --model haiku`로 체크리스트 채점 | `server/tests/persona_eval/` |

**완료 기준**

- 톤 평가 20개 중 18개 이상 통과(NFR-07)
- 텍스트 턴 전송 후 첫 `sentence` 이벤트까지 2초 이내(상주 프로세스 기준, 10회 중앙값)
- "이거 저장해줘"에 `save_note`가 호출되고 `tool` 이벤트가 웹에 표시
- `jenny.yaml`의 이름·말투만 바꿔 서버 재시작 시 코드 수정 없이 반영(NFR-08)
- pytest가 실제 CLI 없이 통과

| S2-09 | 추출 품질 평가 세트: 대화 전문 10개 + 사람이 만든 정답, 비교 스크립트 | `server/tests/extract_eval/` |

- 웹 대화 5회가 각각 일지로 정리되고, 다음 세션에서 제니가 지난 아이디어를 먼저 언급
- 세션 도중 서버를 강제 종료해도 그 직전 턴까지 DB에 남음
- 추출 평가에서 정답 아이디어·할 일의 재현율 80% 이상(기준값은 첫 측정 후 조정)

## 5. 3단계 — 웹 음성 대화 (2~3주)

대상 요구사항: FR-01(화면 버튼), FR-02, FR-03, FR-04, FR-06, NFR-01, NFR-03, NFR-04

| S3-03 | 턴 API 확장: 오디오 업로드 → `transcript` 이벤트 → 문장마다 TTS 후 `sentence`(텍스트 + base64 MP3). TTS는 다음 문장과 병렬로 미리 합성 |
| S3-04 | 끼어들기 `POST /turns/{turn_id}/cancel`: 클라이언트가 보낸 "마지막으로 재생한 문장 번호"까지만 기록하고 CLI 인터럽트, `interrupted=true` 저장 |

| S3-06 | 클라이언트 설정값을 `/profile` 응답에 포함(VAD 임계값, 무음 1.2초, 소음 0.3초 무시, 재생 중 임계값 상향치) |
| S3-07 | 단계별 지연 측정 로그(STT, 첫 토큰, 첫 문장 TTS 완료) |

**웹 클라이언트**

| ID | 작업 |
|---|---|

| S3-11 | `AudioOutput`: Web Audio API로 문장 MP3를 순서대로 이어 재생, 재생한 문장 번호 추적, 즉시 정지 |
| S3-12 | `LocalQueue`: IndexedDB에 발화 보관, 온라인 복구 시 순서대로 전송, 실패 횟수 기록. 오프라인 안내는 `speechSynthesis` |
| S3-13 | 대화 화면 음성 모드: 큰 버튼(한 번 = 시작/끼어들기, 길게 = 종료), 상태 표시, 알림음(`shared/sounds/`), Screen Wake Lock, Media Session 보조 |

| S3-16 | Playwright E2E: 녹음 파일을 가짜 마이크로 넣어 발화 → 답변 → 끼어들기 → 오프라인 복구 흐름 확인 |

- 말을 끝낸 뒤 제니 음성 시작까지 3초 이내(측정 로그 중앙값, NFR-01)
- 실제 등산로 녹음 기준 발화 인식률 측정값 기록(목표 90%, NFR-03)
- 비행기 모드로 3턴 이상 말한 뒤 복구 시 기록 유실 0건(NFR-04)
- 제니 목소리로 인한 끼어들기 오작동 횟수 기록

## 7. 5단계 — 다듬기와 확장 (2주)

## 10. 단계별 점검 항목

각 단계를 끝낼 때 다음을 확인하고 다음 단계로 넘어간다.

- 완료 기준의 측정값을 `docs/progress.md`에 기록(측정 날짜, 환경, 값)
- `CLAUDE.md`와 `client-contract.md`가 실제 코드와 맞는지
- 실제 Claude CLI를 쓰는 통합 테스트를 1회 수동 실행(자동 테스트는 가짜 CLI 사용)
- 구독 사용량을 확인하고, 한도에 가까우면 요약·평가 호출을 haiku로 유지하는지 점검

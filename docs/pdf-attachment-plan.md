# PDF 첨부 계획 (FR-22 확장)

[attachment-plan.md](attachment-plan.md)의 2차 후보. 상태: **구현·검증 완료**(2026-10-22). 한도: PDF 메시지당 1개, 5MB, 파일당 10쪽, 세션 누적 20쪽(P0 실측). 실제 CLI·브라우저로 다운로드 폴더의 보험증권 PDF(5쪽)를 첨부해 질문·후속 질문·일지·내려받기를 확인했다. M0 스파이크에서 CLI의 `document` 블록(base64 PDF)이 동작함을 확인했다([spikes/attachments.md](spikes/attachments.md) 2번).

## 결정

| 항목 | 내용 |
|---|---|
| 형식 | `.pdf`, 매직 바이트 `%PDF-` 확인. 암호화·손상 파일은 거절 |
| 가공 | 재인코딩하지 않고 원본을 저장·전달한다(이미지처럼 줄일 수 없다). `pypdf`로 쪽수·암호화만 읽는다 |
| 한도 | 파일당 원본 용량·쪽수는 스파이크(M0) 토큰 실측으로 정한다. 메시지당 PDF 1개, 세션 누적 쪽수 상한도 둔다 |
| 전달 | `{"type":"document","source":{"type":"base64","media_type":"application/pdf","data":…}}` 블록을 이미지 블록 뒤·텍스트 블록 앞에 둔다 |
| 표시 | 말풍선·일지 전문에는 이름 칩(썸네일 없음). 누르면 원본을 내려받는다(`application/pdf`) |
| 다시 열기·일지 추출 | 이름만(`[첨부: 이름]`). 제니는 내용을 모른다고 말한다 |
| 서빙 | `application/pdf`, `Content-Disposition: attachment`(브라우저 뷰어 렌더 방지), `nosniff` |
| 음성 세션 | 기존처럼 거절 |

## 알려진 한계

- `pypdf`로 쪽수를 세는 동안(최대 10초 제한) 스레드를 중간에 멈출 수 없다. 5MB 안에 페이지 객체를 아주 많이 넣은 PDF는 거절 응답 뒤에도 잠시 CPU를 쓴다. 업로더가 본인뿐이라 감수한다(서비스화 때 별도 프로세스로 분리).
- 웹은 쪽수·세션 누적 쪽수를 미리 검사하지 않는다(서버 400 안내). 이미지 장수와 같은 방식이다.

## 단계

| 단계 | 작업 | 검증 |
|---|---|---|
| P0 | 스파이크: 다운로드 PDF(5쪽)와 합성 PDF(여러 쪽)로 쪽수별 입력 토큰·지연, 거절 시 다음 턴, `--resume` 기억 측정(실제 CLI) → 한도 확정 | `docs/spikes/attachments.md` 갱신 |
| P1 | 서버: 설정 한도, `pypdf` 의존성, 검증·저장(`services/attachments.py`), `document` 블록 전달, 세션 누적 쪽수, 서빙 헤더, `client.attachments` 한도 확장, 규칙 문구 | pytest(위조·암호화·쪽수 초과·크기 초과·누적), ruff |
| P2 | 웹: 형식 목록·한도 안내, 이름 칩, 일지 표시, 스키마 재생성 | vitest, lint, build, `gen:api --check` |

| P4 | 문서(규약·설계서·인계), 서브에이전트 리뷰, 커밋·푸시 | |

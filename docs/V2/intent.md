# TrailTalk V2 intent

> 상태: 초안(제안자 확인 대기). AI 네이티브 SDLC의 1단계 산출물이다. 다음 단계는 spec.md(요구사항·설계), plan.md(구현 계획)이다.
> 이 문서는 "무엇을, 왜, 어디까지"만 적는다. "어떻게"는 spec.md에 쓴다. 근거는 V1 문서(요구사항·설계서, 구현 계획서, handoff, 클라이언트 규약)와 코드다. **[확인 필요]**는 제안자가 정할 부분, **[가정]**은 측정 전 추정이다.

## 1. 한 줄 의도

산책 중 제니와 **사람끼리 말하듯** 대화한다. 말이 끝나면 제니가 곧바로 답하고, 제니가 말하는 도중에 끼어들면 제니가 자연스럽게 멈추고 내 말을 듣는다.

## 2. V2의 초점

| 초점 | 뜻 |
|---|---|
| **답변 시간 단축** | 내 말이 끝난 뒤 제니의 첫 소리가 나오기까지의 시간을 줄인다 |
| **자연스러운 끼어들기** | 제니가 답하는 도중에 말해도 즉시 멈추고, 끼어든 말을 놓치지 않고, 끊긴 뒤 대화가 어색하지 않게 이어진다 |

두 초점이 V2 작업의 우선순위를 정한다. 이 둘과 직접 관계없는 항목은 후순위(8장)로 둔다.

## 3. 문제

V1(웹 앱 PWA + FastAPI, 2026-10-19 기준 63/69 작업, 3단계 36/37)에서 PC 브라우저와 폰으로 음성 대화는 된다. 그러나 대화처럼 느껴지지 않는다.

**답변 시간**

- 말을 끝낸 뒤 제니 음성까지 중앙값 6.6초(목표 3초). 이 값은 무음 대기가 1.2초이던 때의 책상 측정이다. 이후 1.8초로 올라 현재는 더 길 수 있다. 내역: 무음 대기·전송 1.25 + 인식 1.1~1.5 + CLI 첫 글자 1.3 + 첫 문장 완성·합성 2.7(초). (handoff 1장)
- 2026-10-20 폰 실측(시나리오 A 11턴, 현재 코드): 말 끝 → 첫 소리 중앙값 약 6.0초(p90 약 8.1초). 내역은 무음 대기·전송 1.85 + 인식 0.9 + CLI 첫 글자 약 1.4 + 첫 문장 합성 1.57 + 기타 약 0.3(초). 무음 대기가 약 30%를 차지하는 고정 비용이지만, 줄이면 생각하며 쉬는 중간 쉼에서 말이 끊겨 반쪽 말에 답하는 문제(S3-33)가 되살아나므로 V2에서는 줄이지 않는다(7장).
- 합성이 끝난 첫 문장도 다음 CLI 이벤트가 와야 내보내는 구조적 지연이 있다.

**끼어들기** (코드로 확인한 V1 동작)

- 재생 중 말 시작 판정 기준이 높다(`vad.playback_speech_threshold` 0.8, 누적 음성 프레임이 0.3초 분량에 이르러야 인정). 제니 목소리를 사용자 말로 오인하지 않으려는 값이지만, 작은 목소리나 짧은 "응"은 놓치고 반응도 느리다. 정지까지 걸리는 시간은 측정한 적이 없다.
- 소리를 페이드 없이 바로 끊는다.
- 끼어든 순간에도 "듣기 시작" 알림음이 사용자 말 위에 겹쳐 나간다.
- 끼어든 말의 발화 끝 판정에도 평상시와 같은 무음 1.8초가 적용되고, 서버가 이전 턴을 정리하는 시간(최대 10초 대기)이 응답 지연에 섞인다.
- 기록은 문장 단위다. 문장 도중에 끊으면 그 문장은 못 들은 것으로 처리돼 제니가 같은 말을 되풀이할 수 있다.
- 제니 목소리·알림음을 마이크가 다시 잡는 문제(에코)는 브라우저 기본 에코 제거에만 기대고, 이어폰(유선·블루투스) 조건별로 검증한 적이 없다.
- 현장(산책) 검증이 없다. 오작동(헛 끼어들기)과 누락(끼어들었는데 안 멈춤)을 나눠 기록하는 곳도 없다.

## 4. 사용자와 상황

- **1차 사용자**: 매일 아침 산책·등산을 하며 제니와 이야기하는 사람. 현재는 개발자 본인 한 명.
- **상황**: 이어폰(유선·블루투스)을 끼고 걷는다. 스피커로 재생하는 사용은 지원하지 않는다(9장 결정). 바람·숨소리, 불안정한 통신이 있다. 화면은 켜 둔 채 손이나 주머니에 있다.

## 5. 기대 결과

1. **빠른 첫 반응**: 무음 대기(1.8초)를 그대로 두고 그 밖의 구간을 줄여, 짧은 맞장구로 첫 반응을 말 끝 + 약 2.2초 안에 주고 첫 답변을 약 5.3초 안으로 줄인다(현재 약 6.0초에서 첫 문장 합성 등 약 0.7초 단축) **[가정: 수치는 M1 측정 뒤 확정]**. 무음 대기를 줄이는 안(무음 0.9초 가정 시 첫 반응 약 1.4초, 첫 답변 약 4.3초)은 쪼개진 말 문제 때문에 택하지 않는다. 엄격한 3초는 목표에서 내린다.
2. **즉시 멈춤**: 제니가 말하는 중 내가 말을 시작하면 중앙값 0.5초 안에 소리가 멈추고, 그 전에 볼륨이 먼저 줄어든다 **[가정: 수치는 M0 측정 뒤 확정, 소프트웨어 경로 기준이며 블루투스 지연은 실기에서 따로 잰다]**.
3. **놓치지 않는 끼어들기**: 끼어든 말의 앞부분이 잘리지 않고 한 번에 인식된다.
4. **헛 끼어들기 없음**: 이어폰을 낀 상태에서 제니 목소리·알림음·맞장구·바람 소리에 제니가 멈추지 않는다.
5. **끊긴 뒤 자연스러운 이어짐**: 제니가 이미 한 말을 되풀이하지 않고, 내가 못 들은 핵심은 짧게 다시 말한다. 기록에도 실제로 들은 만큼만 남는다.

**성공의 모습**: 개발자 본인이 산책에서 "중간에 말을 자르는 게 편하다, 기다리는 시간이 거슬리지 않는다"고 느끼고 주 5회 이상 쓴다 **[확인 필요: 기준 수치]**.

## 6. 영향 범위

- **서버**: 턴 처리(`app/services/conversation.py`: 턴 실행, 취소, 들은 문장까지 자르기), 문장 분할(`app/voice/sentences.py`), 음성 합성·인식(`app/voice/`), 페르소나 규칙(`app/persona/rules.py`의 끼어들기 안내), 지연 기록(`turn_latency`, `GET /api/latency`).
- **웹**: 상태 머신(`web/src/core/sessionMachine.ts`)과 상태 전이 표(`shared/fixtures/transitions.json`), 입력(`web/src/platform/audioInput.ts`)·출력(`audioOutput.ts`), 음성 컨트롤러(`web/src/screens/voiceController.ts`), 클라이언트 설정(`shared/client-defaults.json`의 `vad.*`).
- **검증 장치**: 지연 평가 스크립트, 끼어들기 평가(정지 지연, 오탐, 누락, 인식, 맥락), Playwright E2E.
- **문서**: `CLAUDE.md`, `docs/client-contract.md`(상태 머신·SSE).

## 7. 제약

- **무음 대기 유지**: 발화 끝 판정 무음(`end_of_speech_silence_ms` 1800)은 줄이지 않는다. 걸으며 생각하느라 쉬는 말이 끊기면 반쪽 말에 답하기 때문이다(S3-33). 지연은 합성·서버 턴 경로·맞장구로 줄인다. 현장 데이터(이어 말하기, 소음)가 충분히 쌓인 뒤에만 다시 검토한다. 대신 쉬며 이어 말한 말이 쪼개져 앞말에만 답하는 문제는 큐 뒷말 즉시 전송(병합)으로 줄인다(2026-10-20 시나리오 E, 사용자 결정).
- **핸즈프리 우선**: 시작은 화면 버튼 한 번, 이후 조작 없이 진행·종료.
- **클라이언트는 얇게**: 문장 분할·요약·페르소나는 서버. `web/src/core/`는 브라우저 API 비의존 순수 TypeScript.
- **페르소나 분리(V1 NFR-08)**: 캐릭터 이름·말투·보이스·맞장구 문구는 `server/personas/*.yaml`에만.
- **기록 유실 0**: 턴은 오가는 즉시 저장하고, 끼어들기로 끊긴 턴도 들은 만큼 정확히 남는다.
- **개인정보는 본인 서버에**, **API 키 없이 Claude 구독**(Claude CLI), 호출은 `LlmSessionManager`로만.
- **이어폰 전제**: 스피커 재생 중 끼어들기·에코는 지원 대상이 아니다. 스피커로 쓰면 헛 끼어들기가 날 수 있다는 점을 설정 화면에 안내만 한다.
- **웹 한계 수용**: 화면 꺼짐·백그라운드 중단은 막지 못한다.
- **회귀 금지**: 이어 말하기(S3-33), 쉬기·끝내기 음성 명령, 오프라인 큐를 깨지 않는다. 상태 머신을 바꾸면 `transitions.json`을 함께 고친다.
- **작업 방식**: 마일스톤마다 구현·검증·사용자 확인 후 다음으로. 유닛 테스트와 Playwright 실구동, 서브에이전트 diff 리뷰 후 자동 커밋·푸시(저장소 `CLAUDE.md` 규칙, 2026-10-20 지시로 복원).

## 8. 이번에 하지 않는 것 (후순위)

삭제가 아니라 V2의 두 초점이 끝난 뒤 다시 고른다.

| 항목 | 이유 |
|---|---|
| 답변 시간 단축 작업 전체(M1: 서버 턴 경로, 첫 문장 짧게, 맞장구, 큐 뒷말 즉시 전송 포함) | 2026-10-20 사용자 지시로 **일시 보류**. 다른 작업(M0 잔여, 끼어들기 M2, 보안 M3)이 끝난 뒤 사용자가 지시하면 다시 시작한다. 이 문서의 1번 초점(빠른 첫 반응)은 그때 되살린다 |
| 무음 대기 단축, 투기적 조기 전송(말이 끝나기 전 STT·CLI 선시작) | 무음을 유지하기로 했다(7장). 큐 뒷말 즉시 전송(병합)은 2026-10-20 시나리오 E(쉬며 말한 6회 중 5회가 쪼개져 앞말에만 답함) 결과로 사용자가 채택해 M1에 포함한다 |
| 일지 품질(제니 제안과 사용자 결정 구분, 근거 턴, 검색·내보내기, 오인식 표시) | 초점 밖. 다만 끊긴 답변이 일지 추출에 미치는 영향은 작게 확인한다 |
| 화면 꺼짐·백그라운드 복구, 오프라인 문구의 페르소나 이동 | 초점 밖 |
| 주간 브리핑, 제니가 먼저 말 걸기(D4), 일지 조회 MCP | 초점 밖, 결정 대기 |
| 서비스화·멀티 사용자(D6), 네이티브 앱 | 범위 밖 |
| 인증(`/api` 접근 제한)·Origin 검사 | 실제 위험이라 지우지 않는다. 두 초점 뒤 최소 범위로 진행 **[확인 필요: 순서]** |

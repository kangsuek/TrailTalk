# 국내 뉴스 검색 도구 평가 — 2026-10-21 (NV-08)

네이버 뉴스 검색 도구(`search_naver`)와 라우팅 규칙을 넣은 뒤, 실제 Claude CLI와 실제 검색 API(네이버, Tavily)로 도구 선택과 응답 시간을 쟀다. 평가용 서버(임시 DB)에 텍스트 모드로 새 세션마다 한 질문씩 보냈다. 시간은 요청을 보낸 시점부터 잰 값이다(CLI 기동 제외). 어떤 도구가 실제로 쓰였는지는 서버의 검색 로그로 판별했다.

- 구성 A(새): 최종 규칙(국내 `search_naver`, 해외 `search_USA`, 내장 `WebSearch` 폴백) — 9문항 × 2회
- 구성 B(기준선): 두 검색 API 도구를 등록하지 않고 Tavily 이전 규칙(내장 검색만) — 5문항 × 2회

## 도구 선택(라우팅)

| 분류 | 질문 | 기대한 도구 | 결과 |
|---|---|---|---|
| 국내, 지정 없음 | 오늘 국내 증시 현황을 알려줘. / 최근 부동산 대책 뉴스 알려줘. / 삼성전자 최근 실적 알려줘. | `search_naver` | 6/6 일치 |
| 매체 지정 | YTN 뉴스에서 오늘 증시 소식 알려줘. | `search_naver` (`site=ytn.co.kr`) | 2/2 일치. 입력에 `site=ytn.co.kr`, 검색어에 "YTN" |
| 국내 사이트 지정 | 국내 사이트에서 엔비디아 관련 뉴스 찾아줘. | `search_naver` | 2/2 일치 |
| 해외 사이트 지정 | 해외 사이트에서 엔비디아 AI 반도체 최신 뉴스 찾아줘. | `search_USA` | 2/2 일치 |
| 해외, 지정 없음 | 미국 증시 현황을 알려줘. / 엔비디아 AI 반도체 최신 뉴스 알려줘. | `search_USA` | 4/4 일치 (뒤의 질문은 `search_USA` 후 한국 언론 교차 확인으로 `search_naver`도 씀) |
| 검색 불필요 | 산책 코스를 고를 때 중요한 점이 뭐야? | 검색 안 함 | 2/2 일치 |

- 18건 모두 의도한 도구를 썼다. 내장 `WebSearch`로 넘어간 경우는 없었다(오류가 없었다).
- 엔비디아 AI 반도체 질문은 `search_USA`를 먼저 부르고 이어서 `search_naver`로 한국 언론 교차 확인을 했다. AI 반도체 뉴스 규칙("한국 언론은 미국 보도와 맞는지 교차 확인")이 의도한 동작이다.
- 평가 스크립트가 한 질문의 사용 도구를 고정된 순서(네이버, 미국)로 표기해 이 질문을 "불일치"로 찍었는데, 호출 순서는 규칙대로(미국 먼저)였다. 아래 원자료 표의 해당 행이 이 표기다.

## 응답 시간

| 구성 | 문항 | 도구 첫 완료(중앙값) | 전체 응답(중앙값) | 검색 호출 수/턴(평균) |
|---|---|---|---|---|
| A 새 규칙 | 국내 4문항(8턴) | **2.0초** | **6.3초** | 1.2 |
| B 내장 검색만 | 국내 4문항(8턴) | 8.5초 | 22.7초 | 2.9 |
| A 새 규칙 | 미국 증시(2턴) | 3.2초 | 9.8초 | 1.5 |
| B 내장 검색만 | 미국 증시(2턴) | 7.0초 | 22.7초 | 4.0 |

- 국내 질문의 전체 응답이 22.7초에서 6.3초로 줄었다. 검색 호출 수도 턴당 평균 2.9회에서 1.2회로 줄었다(구성 A는 8턴 중 2턴이 2회 호출).
- 위 시간에는 모델 시간이 섞여 있다. 네이버 API 호출 자체는 어댑터 로그 기준 약 0.04~0.12초였다(스파이크와 실제 호출 확인 때의 로그).
- 같은 날 폰 검증에서는 `search_USA`(Tavily)로 국내 질문을 하면 미국 매체만 나와 모델이 "오늘 장 상황은 확인된 자료가 없다"고 답했다(관찰, 이 표의 측정이 아님). 새 구성에서는 오늘 개장 시황을 한국 매체로 인용해 답했다(아래 발췌).

## 품질 확인(답변 발췌)

아래는 1차 실행(규칙 문구 수정 전)의 답변에서 발췌했다. 수정 후 재실행에서도 도구 선택과 호출 수는 같은 패턴이었다.

- 국내 증시: 어제 마감(코스피 3.73% 급락, 5552.74)과 오늘 개장 반등(5700선 회복)을 구분하고 매체 이름(뉴스퀘스트, 뉴스1 등)을 붙였다.
- YTN 지정: 입력에 `site=ytn.co.kr`을 넣었고 답변이 "YTN 기사(오늘 오전 10시대 기준)에 따르면"으로 출처를 밝혔다.
- 부동산 대책: 최근 일주일 기사에서 대출 한도 소식과 재산세 소식을 찾아 매체(한국일보 계열, YTN)를 밝히고, "새 대책이 발표됐다는 기사는…"처럼 자료의 한계를 말했다.

## 한계

- **계획서 NV-08의 비교 중 일부만 수행했다.** 측정한 것은 `search_naver`(새 구성) 대 내장 `WebSearch`의 응답 시간과 호출 수, 도구 선택 일치다. 국내 질문에 대한 `search_USA`의 정량 비교는 따로 재지 않았고(폰 검증 관찰만 있음), 국내 매체 인용률과 최신성은 표로 비교하지 않고 답변 발췌로만 확인했다. 시험 질문에 정치 소식은 없다(부동산 대책이 정책 소식 사례).

- 표본이 작다(구성 A 18턴, B 10턴). 시간은 중앙값이고 정밀한 수치는 아니다.
- 텍스트 모드라 음성의 5문장 제한과 합성 시간은 들어 있지 않다.
- 네이버 요약(`description`)이 짧아서, 자세한 설명이 필요하면 `WebFetch`가 한 번 더 든다(이번 평가에서는 호출하지 않았다).
- 폰 음성 검증(NV-09)은 사용자 기기에서 따로 한다.

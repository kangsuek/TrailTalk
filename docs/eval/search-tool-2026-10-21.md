# 검색 도구 지연 비교 — 2026-10-21 (TS-10)

Tavily 검색 도구(`search_web`)를 쓸 때와 내장 `WebSearch`만 쓸 때의 검색 턴 응답 시간을 비교했다. 실제 Claude CLI(대화 모델)와 실제 Tavily API를 썼고, 평가용 서버(임시 DB)에 텍스트 모드로 새 세션마다 한 질문씩 보냈다. 시간은 요청을 보낸 시점부터 잰 값이다(CLI 기동 제외).

- 질문 2개 × 3회 = 6턴씩: "엔비디아 AI 반도체 최신 뉴스 알려줘.", "미국 증시 현황을 알려줘."
- 구성 A(새): 새 규칙(`search_web` 우선) + `search_web` 등록
- 구성 B(기준선): M2 이전과 같게 `search_web` 미등록 + 이전 규칙(내장 검색만)
- 구성 C(참고): 이전 규칙 + `search_web` 등록(규칙을 안 바꿔도 모델이 어느 도구를 고르는지 확인)

## 결과

| 구성 | 선택한 도구 | 도구 첫 완료(중앙값) | 전체 응답(중앙값) | 전체 응답 범위 | 검색 호출 수/턴 |
|---|---|---|---|---|---|
| A 새 규칙 + search_web | search_web 6/6 | **2.3초** | **9.5초** | 8.0~12.2초 | 2 (6턴 모두) |
| B 내장 검색만(기준선) | WebSearch 6/6 | 7.2초 | 26.2초 | 20.3~30.1초 | 3~4 |
| C 이전 규칙 + search_web | search_web 6/6 | 2.4초 | 11.4초 | 6.9~16.6초 | 2~3 |

- 검색 도구가 끝나기까지의 시간이 7.2초에서 2.3초로, 전체 응답이 26.2초에서 9.5초로 줄었다(약 1/3).
- 내장 검색은 한 턴에 3~4번 호출하며 시간이 쌓였다.
- **최신성은 새 도구가 낫지 않았다.** 미국 증시 질문에서 내장 검색은 3회 중 2회 어제(20일) 마감 수치를 찾았고 1회는 "7일 이내 자료를 찾지 못했다"며 15일 자료로 답했다. 새 도구는 3회 모두 월요일(19일) 마감까지 답하고 "화요일(20일) 장은 확인하지 못했다"고 했다. 엔비디아 뉴스는 두 구성 모두 7일 이내 자료로 답했다.
- 최종 규칙(recency=week/day, 재검색 횟수 명시)으로 A를 다시 6턴 재측정한 값도 비슷했다: 도구 첫 완료 2.3초, 전체 응답 9.0초(6.7~13.7초), `search_web` 6/6.
- 구성 C에서도 모델이 `search_web`을 골랐다. 도구 설명이 "내장 WebSearch보다 먼저"라고 안내하기 때문이다. 규칙 변경(TS-08)은 폴백 순서와 7일 규칙을 도구 인자(`recency=week`)에 맞추는 역할이다.

## 후속 확인: 검색 깊이 fast vs basic

새 도구가 20일 마감을 못 찾은 원인을 보려고 Tavily를 직접 호출했다(뉴스, `time_range=week`, 5건, 질의당 2회). 20일 기사는 Tavily에 있었다.

| 질의 | fast 최신 발행일 | basic 최신 발행일 |
|---|---|---|
| 미국 증시 현황 | 10-20 | 10-20 (20일 기사 2건) |
| US stock market close Tuesday | **10-17** | 10-20 (20일 기사 3건) |
| Wall Street stocks close | 10-20 | 10-20 |

- 같은 질의를 반복하면 두 깊이 모두 0.8초대로 돌아온다(캐시로 보임). 첫 호출은 `fast` 0.8~1.4초, `basic` 4~7초였다.
- 즉 모델이 어떤 검색어를 쓰느냐에 따라 `fast`가 최신 기사를 놓칠 수 있고, `basic`은 더 안정적이지만 첫 호출이 3~5초 느리다. 기본값은 `fast`로 두고(`SEARCH_DEPTH=basic`으로 전환 가능), 폰 검증(TS-11)에서 실제 질문으로 최신성 놓침 빈도를 보고 정한다.

## 한계

- 표본이 작다(구성당 6턴). 중앙값 차이는 크지만 정밀한 수치는 아니다.
- 텍스트 모드라 음성의 5문장 제한, 합성 시간은 들어 있지 않다.
- 구독 사용량이 있는 실제 CLI라 시간 변동이 있다.
- 답변 끝에 `Sources: [..](URL)` 링크 목록이 붙는 일이 A에서 5/6, B에서 6/6 있었다. 이번 변경으로 생긴 문제는 아니고 텍스트 대화에서의 습관이며, 음성은 TTS가 URL과 마크다운을 지운다. 폰 검증(TS-11)에서 확인한다.
- Tavily 크레딧은 구성 A 6턴에서 약 12, 구성 C 6턴에서 약 14, A 재측정 6턴에서 약 13, 후속 확인 직접 호출 12회로 합계 약 50 소모했다(호출당 1크레딧 가정, 무료 월 1,000 중).

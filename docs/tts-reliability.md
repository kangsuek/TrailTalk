# 음성 합성(TTS) 메모

> 상태: **해결됨(2026-10-21).** `.env`의 `TTS_MODEL=tts-1`로 합성 멈춤이 사라졌다(검색 답변 5턴 재시도·실패 0건, 사용자 확인). 이 문서는 나중에 `gpt-4o-mini-tts`로 돌아가거나 합성 문제가 다시 생길 때 필요한 것만 남긴다.

## 1. 원인과 현재 설정

- **원인**: OpenAI `gpt-4o-mini-tts`가 요청을 받고도 **응답을 시작하지 않고 멈춘다**(응답 헤더 전 읽기 시간 초과). 2026-10-20 실측(실제 호출 약 190회)에서 13~30%였다. 응답이 시작되면 빠르다(최대 3초대).
- 네트워크·문장 내용·말투 지시(`instructions`)와 무관했다(IPv4 전용·연결 재사용·말투 지시 제거로 달라지지 않음, 문장 5종 모두 같은 비율).
- **`tts-1`·`tts-1-hd`는 72번 중 멈춤 0번**이었다(`tts-1` 중앙 2.2초, 최대 3.8초).
- **현재 설정**: `.env`의 `TTS_MODEL=tts-1`(보이스 `nova`). `tts-1`은 말투 지시를 받지 않아 밝은 말투 표현이 약해진다(`tts.py`의 `_style`이 모델 이름으로 분기).
- 요청 재시도 코드는 유지한다: `openai_http.post`의 `attempts`, 설정 `tts_timeout_s=8`·`tts_attempts=3`(`server/app/config.py`). `tts-1`에서는 거의 동작하지 않는다.

## 2. 가격 (OpenAI 공식, 2026-10 확인)

| 모델 | 과금 | 단가 |
|---|---|---|
| `tts-1` | 입력 글자 수 | $15 / 100만 글자 |
| `tts-1-hd` | 입력 글자 수 | $30 / 100만 글자 |
| `gpt-4o-mini-tts` | 입력 텍스트 토큰 + 출력 오디오 토큰 | 입력 $0.60 / 100만 토큰, 출력 $12 / 100만 토큰 |

추정(한 턴 약 250자, 약 40초 분량 가정): `tts-1`이 한 턴 약 $0.004, `gpt-4o-mini-tts`가 약 $0.010으로 `tts-1`이 **약 2.5~3배 저렴**하다. `gpt-4o-mini-tts`는 말하는 시간에 비례해 비용이 오른다. 두 모델 모두 금액은 작다.

## 3. 다시 `gpt-4o-mini-tts`로 돌아갈 때 (말투를 되살리고 싶을 때)

`.env`에서 `TTS_MODEL` 줄을 지우면 돌아간다. 멈춤이 다시 생기므로 아래 대책이 필요하다.

1. 시도당 제한을 8초 → 4.5초로 줄인다(성공 응답은 대개 3초 안, 최대 6.9초 관측).
2. 헤징: 첫 요청이 3초 안에 응답하지 않으면 끊지 않고 둘째 요청을 동시에 보내 먼저 오는 쪽을 쓴다. 마지막 시도는 `tts-1`로 보낸다(보이스 매핑 필요). 취소(끼어들기) 시 모든 요청이 취소되는지 테스트한다.
3. 동시 합성 수(`server/app/voice/speech.py` `MAX_CONCURRENT=3`)를 늘린다.

## 4. 남은 구조적 약점 (모델과 무관)

- 문장은 순서대로 보내서 맨 앞 문장 합성이 오래 걸리면 뒤 문장도 함께 밀린다(`conversation.py` `next_sentence`).
- 도구 시작 때 검색 안내 음성을 인라인으로 합성한다(`conversation.py` 약 806~833행, `speech.cached`). 이 합성이 느리면 CLI 이벤트 읽기가 멈춘다. 앱 시작·보이스 변경 때 미리 캐시하면 막히지 않는다.
- 서버가 소리 없이(`audio: null`) 보낸 문장은 클라이언트가 조용히 건너뛴다. 서버 주석(`speech.py`)은 기기 TTS로 대신한다고 하지만 **구현돼 있지 않다**(`web/src/platform/audioOutput.ts`). 합성이 끝내 실패하면 완전한 무음이다.
- 로그에 시도 번호·모델·문장 길이·연결/읽기 단계 구분이 없어 소리가 빠진 빈도를 세기 어렵다.

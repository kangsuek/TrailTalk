# 네이버 뉴스 검색 도구 개발 계획 (NV)

국내 뉴스·증시 질문의 검색 품질을 올리기 위해 네이버 뉴스 검색 API를 MCP 도구 `search_naver`로 추가한다. 배경은 [tavily-search-plan.md](tavily-search-plan.md) M4 폰 검증(2026-10-21)이다. NV-01 스파이크는 완료했다(키 확인, 결과: [spikes/naver-news.md](spikes/naver-news.md)). 구현은 사용자 확인 후 시작한다.

## 1. 배경: 왜 필요한가

폰 검증에서 국내 증시 질문(3회, 검색 15건)에 `search_USA`(Tavily)가 한국 매체를 한 건도 돌려주지 못했다. 실험 결과:

| 시험 | 결과 |
|---|---|
| 한국어 국내 증시 검색 (`search_USA`) | 미국 매체(MarketWatch, CNBC, Yahoo)와 무관한 기사(NBA 일정)만 나옴 |
| `ytn.co.kr` 도메인 지정 | YTN 기사는 나오나 발행일이 비어 최신 여부를 알 수 없음 |
| 한국 매체 10곳 지정 (뉴스 주제) | 1~3건, 주제와 무관 |
| 한국 매체 지정 (일반 주제) | 코스피 2350선·9000선 같은 몇 년 전 시황이 섞임 |
| 국가 지정(`country`) | `fast` 깊이에서는 400 오류 |
| 내장 `WebSearch` | 코스피 3.73% 하락 마감 5,552.74를 한국 매체로 인용(단, 16~21초) |

결론: Tavily 뉴스 색인에는 한국 매체가 거의 없다. 한국 뉴스용 검색원이 따로 필요하다.

## 2. 네이버 뉴스 검색 API 사양 (공식 문서 확인)

출처: https://developers.naver.com/docs/serviceapi/search/news/news.md

| 항목 | 내용 |
|---|---|
| 호출 | `GET https://openapi.naver.com/v1/search/news.json`, HTTPS |
| 인증 | 헤더 `X-Naver-Client-Id`, `X-Naver-Client-Secret` (개발자 센터에서 애플리케이션 등록 후 발급, 검색 API 사용 설정 필요. 안 켜면 403) |
| 파라미터 | `query`(필수, UTF-8), `display`(1~100, 기본 10), `start`(1~1000), `sort`(`sim` 정확도 기본 / `date` 날짜순) |
| 응답 | `items[]`: `title`·`description`(검색어 일치 부분이 `<b>` 태그), `originallink`(원문 URL), `link`(네이버 뉴스 URL), `pubDate`(`Mon, 26 Sep 2016 07:50:00 +0900`, 네이버에 제공된 시간). 최상위 `total`, `start`, `display`, `lastBuildDate` |
| 오류 | `SE01`~`SE04`·`SE06` 400, `SE05` 404, `SE99` 500, 권한 없음 403 |
| 한도 | 검색 API 전체 하루 25,000회 (클라이언트 아이디별 합산) |
| 없는 것 | **날짜 범위 필터**, **언론사 이름 필드**, 기사 전문(요약 패시지만) |

## 3. 도구 설계

### 3.1 라우팅 (사용자 제안 반영)

| 상황 | 사용할 도구 |
|---|---|
| 사용자가 "해외 사이트에서", "영어권 뉴스" 등을 말함 | `search_USA` (Tavily, 해외·영어권) |
| 사용자가 "국내 사이트에서", "네이버에서", "국내 뉴스" 등을 말함 | `search_naver` (네이버 뉴스) |
| 지정이 없고 한국 관련(국내 증시·정치·지역·한국 매체 이름) | `search_naver` **(미확정: 사용자 확인 필요)** |
| 지정이 없고 해외·글로벌·영어권 | `search_USA` |
| 선택한 도구가 오류이거나 결과가 없음 | 내장 `WebSearch`로 폴백 |

### 3.2 `search_naver` 인자

| 인자 | 설명 |
|---|---|
| `query` | 검색어(2~200자) |
| `recency` | `day`/`week`/`month`. 네이버에 날짜 필터가 없어서 `sort=date`로 받아 발행일로 직접 거른다. 생략하면 `sort=sim` |
| `site` | 선택. 매체 도메인(예: `ytn.co.kr`). 결과의 `originallink` 호스트가 일치하는 것만 남긴다. 검색어에 매체 이름도 넣는다(예: "YTN 증시"). 어댑터가 검색어를 두 가지(원래 검색어, 도메인을 붙인 검색어)로 동시에 요청해 합친다(스파이크 5절) |

- `recency` 또는 `site`를 쓰면 `sort=date`, `display=50`으로 받아 거른 뒤 최대 5건을 돌려준다(`day`=최근 24시간, `week`=7일, `month`=30일). 지정이 없으면 `sort=sim` 5건. 근거는 스파이크 3절(date 정렬도 관련도 50/50 유지).
- 결과 형식은 `search_USA`와 같다(제목·매체(호스트)·발행일·URL·내용). 구조화 결과도 같아서 출처 저장과 화면은 바꾸지 않고, 공개 이름도 `web_search`로 매핑한다.
- 요약이 짧으므로 상세가 필요하면 규칙으로 `WebFetch`(원문 URL)를 쓰게 한다.

## 5. 위험과 대응

| 위험 | 대응 |
|---|---|
| 키 없음·잘못된 키·403(검색 사용 안 켬) | `unavailable`로 분류하고 내장 `WebSearch` 폴백. NV-01에서 키 설정 안내 |
| 요약(`description`)이 짧아 설명이 얕음 | 규칙으로 필요할 때 `WebFetch`(원문). 지연 증가는 NV-08에서 측정 |
| `pubDate`는 기사 작성이 아니라 네이버 제공 시각 | 보고서에 명시. 7일 규칙에서는 큰 영향 없음 |
| `sort=date`의 관련도 | 스파이크에서 4개 검색어 모두 50/50 관련. 기간 지정이 있을 때만 날짜순, 거른 결과가 적으면 있는 만큼만 돌려줌 |
| 매체 이름이 없음 | 호스트(`ytn.co.kr`)를 주고 모델이 매체 이름으로 말하게 함 |
| 하루 25,000회 | 개인용 사용량으로 충분. 429는 폴백 |
| 라우팅 오판(모델이 도구를 잘못 고름) | NV-08·NV-09에서 도구 선택 일치율 확인 |

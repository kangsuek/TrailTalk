# TrailTalk 구현 계획서

- 기준 문서: [requirements-design.md](requirements-design.md) (이하 "설계서")
- 최종 갱신: 2026-10-21

완료한 작업(0~2단계 전체, 3단계 대부분, 5단계 S5-01·S5-07 구현)의 작업 표·세부 체크리스트·완료 기준·변경 이력은 지웠다. 원문은 git 이력에서 볼 수 있다(`git log -- docs/implementation-plan.md`). 이 문서에는 아직 끝나지 않은 것만 남긴다.

## 1. 문서 사용법

설계서의 단계별 계획을 마일스톤과 작업 단위로 나누고, 남은 작업의 진행 상태를 이 문서에서 관리한다. 작업 ID(예: `S3-17`)는 Claude Code에 "S3-17 구현"처럼 요청하는 단위다.

**상태값**: `완료` · `진행 중` · `대기` · `막힘`(사유를 비고에 적는다) · `취소`(하지 않기로 한 단계·작업)

**갱신 규칙**

1. 작업을 시작하면 상태를 `진행 중`으로 바꾸고, 대시보드의 "현재 작업"을 갱신한다.
2. 세부 단계를 끝낼 때마다 체크박스를 `- [x]`로 바꾼다.
3. 작업이 끝나면 상태를 `완료`로 바꾸고 커밋 해시를 적는다. 완료한 작업은 다음 갱신 때 이 문서에서 지우고 git 이력에 맡긴다.
4. 마일스톤(단계)이 끝나면 완료 기준 표의 측정값·결과, 진행 대시보드, 요구사항 추적표를 갱신한다.
5. 요구사항 추적표에는 아직 `완료`가 아닌 요구사항만 둔다.
6. 커밋 해시는 커밋 전에는 알 수 없으므로, 해당 커밋 직후 다음 갱신 때 채운다.

**이월 참고 (남은 한계)**
- 도구를 쓴 턴은 CLI가 도구 뒤 답변을 한꺼번에 내보내 첫 문장이 늦다(실측 도구 끝 후 약 4.7초). 답변의 마크다운(`**굵게**`, 링크)은 화면에 그대로 보인다(음성은 `speech_text`가 지움). `web/src/core`의 브라우저 API 비의존은 아직 린트로 막지 않는다.
- 중복 제거의 유사도 규칙(0.8)은 '월요일/화요일 회의 자료 준비'처럼 한 낱말만 다른 항목을 같다고 볼 수 있다. 일지 상세의 화자 이름은 현재 프로필의 페르소나다(세션에 persona_id가 없다). 추출 평가 세트는 가짜 대화라 쉬우므로 실제 일지로 재측정이 필요하다.
- 음성 턴에서 CLI가 오류로 끝나면 합성 대기 중이던 문장은 보내지 않는다(보낸 문장까지 저장은 유지). 끝내기 요청이 락 대기에서 cancel보다 앞서면 일지 정리가 자르기 전 원문을 읽을 수 있다(웹은 cancel을 먼저 보내 보통 문제 없음). 연결 끊기와 cancel이 겹치면 인터럽트가 두 번 갈 수 있다. VAD 수치는 시작값이라 실제 산책 측정으로 조정한다.
- 처리 중 소음(바람·차·옆 사람)이 0.3초 넘게 말소리로 잡히면 첫 답변이 취소되고 그 소리가 다음 턴으로 가 `no_speech` 안내가 날 수 있다. 무음 대기(1.8초)가 길어 말 끝 → 첫 소리 지연도 그만큼 늘었다. 쉬며 이어 말하면 뒷말이 별도 턴이 되어 앞말에만 답한다(실측 6회 중 5회).
- 전문 검색이 키워드 검색이라 동의어를 못 찾는다. 모델 변경 직후 첫 답변은 CLI 재기동만큼 늦다. 사용량 표시는 서버 재시작 직후 값이 없고 갱신이 최대 30초 늦다. 다른 기기의 진행 중 대화를 여기서 끝내거나 이어받을 수 있다.

## 1. 문서 사용법

설계서의 5단계 개발 방법을 0~5단계 마일스톤과 작업 단위로 나누고, 각 작업의 세부 단계와 진행 상태를 이 문서 하나에서 관리한다. 작업 ID(예: `S1-03`)는 Claude Code에 "S1-03 구현"처럼 요청하는 단위다.

**상태값**: `완료` · `진행 중` · `대기` · `막힘`(사유를 비고에 적는다) · `취소`(하지 않기로 한 단계·작업)

**갱신 규칙**

1. 작업을 시작하면 작업 목록 표의 상태를 `진행 중`으로 바꾸고, 대시보드의 "현재 작업"을 갱신한다.
2. 세부 단계를 끝낼 때마다 체크박스를 `- [x]`로 바꾼다.
3. 작업이 끝나면 상태를 `완료`로 바꾸고 커밋 해시를 적는다.
4. 마일스톤(단계)이 끝나면 완료 기준 표의 측정값·결과, 진행 대시보드, 요구사항 추적표, 변경 이력을 갱신한다.
5. 요구사항 추적표의 상태는 관련 작업이 모두 `완료`이고 검증 단계의 완료 기준을 통과하면 `완료`, 일부만 끝났으면 `진행 중`으로 적는다.
6. 커밋 해시는 커밋 전에는 알 수 없으므로, 해당 커밋 직후 다음 갱신 때 채운다.
7. 단계가 닫히면 완료한 작업의 세부 체크리스트와 마일스톤 종료 체크리스트는 지우고, 작업 표 한 줄·완료 기준·이월 참고만 남긴다(상세는 git 이력). 다른 문서가 참조하는 작업 절은 남긴다.

## 7. 4단계 — 안드로이드 포팅(취소)

**취소(2026-10-19)**: 안드로이드 네이티브 앱으로 포팅하지 않고, 웹 앱(PWA)으로 마무리한다. 작업 S4-01~S4-09(프로젝트·상태 머신 포팅·오디오·오프라인 큐·Foreground Service·이어폰 버튼·Compose 화면·실기기 테스트)는 하지 않는다. 5단계 번호와 작업 ID는 기록 보존을 위해 그대로 둔다.

- 이어폰 버튼은 웹의 Media Session API 보조(S3-13)로 두고, 화면 꺼짐 유지는 Screen Wake Lock으로 대신한다. 화면이 꺼지거나 탭이 백그라운드로 가면 듣기가 멈출 수 있는데, 이는 웹 앱의 한계로 받아들인다.
- 요구사항 중 FR-05·NFR-02·NFR-05는 안드로이드 전용 목표였으나 웹 기준으로 낮춰 3단계에서 확인한다(설계서 2장).
- `web/src/core/`를 UI·브라우저 API 비의존 순수 TypeScript로 두는 규칙은 테스트하기 쉬운 구조를 위해 유지한다.

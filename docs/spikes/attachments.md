# 파일 첨부 스파이크 M0 (2026-10-21)

실제 Claude CLI 2.1.304(구독, `claude-sonnet-5-5`, 도구·설정 없음)로 stream-json 입력의 `content` 블록 배열을 시험했다. 사용자 서버·DB는 쓰지 않았다. 호출 약 20회.

| # | 질문 | 결과 |
|---|---|---|
| 1 | `image`(base64) + `text` 블록이 되는가 | **된다.** 이미지에 쓴 글자(BANANA-7319)를 정확히 읽었다. 이미지가 앞이든 뒤든 같은 답·같은 토큰(3,083/3,079) |
| 2 | `document`(PDF) 블록 | **된다.** 한 쪽짜리 PDF 증가 약 1,600토큰. 2차 후보 |
| 3 | 토큰 | 이미지 1장(1568×1000 JPEG) 입력 증가 **약 2,150**(바탕 928 대비). 이후 4턴은 캐시 읽기로만 잡힘(턴당 새 캐시 생성 62). 한글 텍스트 3만 자는 **약 3만 토큰**(글자당 1토큰), 이후 턴은 캐시 읽기 |
| 4 | 프로세스 종료 뒤 `--resume` | 이전 이미지 내용을 기억한다(캐시 읽기 3,221에 이미지 포함) |
| 5 | 깨진 이미지 뒤 다음 턴 | 그 턴은 "처리 못했다"고 답하고, **다음 턴은 정상**. 컨텍스트 오염 없음 → `cli_session_id` 폐기 폴백 불필요 |
| 6 | 큰 이미지 | 18.7MB PNG(stream-json 한 줄 25MB)도 파이프·파서 문제 없이 처리 |
| 7 | 구성 | 첨부 없는 한 턴의 바탕(시스템 프롬프트 최소) 928토큰. 이 시험은 앱 프롬프트·도구 정의를 쓰지 않아 그 크기는 여전히 추정이다 |

## 결정에 반영

- 1 통과 → 이미지 포함 진행. PDF는 1차 범위 밖 유지.
- 3: 이미지 증가가 기준(약 1,500)을 넘으므로 **긴 변 상한을 1568 → 1024px**로 낮춘다(토큰 약 픽셀수/750, 1024×768 약 1,050).
- 3: 한글 3만 자가 약 3만 토큰이라 텍스트 한도를 **메시지 합계 1만 자, 세션 누적 3만 자**로 낮춘다(파일당 200KB는 유지).
- 5: 서버가 재인코딩한 이미지만 보내므로 별도 폴백 없음.

# 화자 인식 스파이크: OpenAI diarize 실측 (S3-35, 2026-10-18)

여러 참가자의 목소리를 등록하고(`known_speaker_names[]`·`known_speaker_references[]`) 대화 중 화자별로 나눠 받으며, 등록하지 않은 소리(TV·행인)는 버릴 수 있는지 `gpt-4o-transcribe-diarize`로 쟀다.

- 스크립트: [speaker-diarize/](speaker-diarize/) — `make_clips.py`(TTS로 참가자 흉내 오디오), `check_diarize.py`(측정). `server/`에서 `SPIKE_DIR=<임시> uv run python ../docs/spikes/speaker-diarize/<파일>.py`
- 참가자 흉내: 다니엘=onyx, 강석=ash, 필재=verse(일부러 비슷한 남성 보이스), 미등록 TV=coral(여성), 행인=ballad(남성), 제니=nova. 16kHz 모노 WAV
- 등록 클립: 짧은 것("저는 다니엘입니다", 2.2~2.5초), 앞 0.3초 무음 + 뒤 채움(2.5~2.8초), 긴 자기소개(5.8~7.6초)
- 비용: TTS 19문장 + 인식 호출 35회, 약 0.05달러

## 결과 요약

| 항목 | 결과 |
|---|---|
| 짧은 등록 클립(2.2초), 같은 이름 클립 여러 개 | 둘 다 오류 없이 받는다 |
| 세 사람 차례 발화(`mix_three`) 화자 맞추기 | **틀림**. 짧은 클립 2회는 강석 말까지 다니엘로, 긴 클립 5회(같은 이름 여러 클립 포함)는 다니엘 말을 강석으로 붙임. 필재만 맞음 |
| 빠른 차례 발화(`mix_quick_turns`) | 맞음(3명 모두) |
| 미등록 TV(여성) 뒤 강석 | **TV를 등록 화자 "필재"로 붙임** — 걸러지지 않음 |
| 미등록 행인(남성)만 | **"필재"로 붙임** |
| 다니엘 말 뒤로 TV가 작게 깔림 | 다니엘·`A`(미등록 라벨)로 나뉨. 이 경우만 미등록 라벨이 나옴 |
| 제니 메아리(등록 안 함) | "필재"로 붙임 |
| 제니를 known speaker로 등록(4명) | "제니"로 붙어 걸러낼 수 있음 |
| known speaker 없이 | `A`·`B`로 나뉘지만 첫 두 사람을 한 사람(`A`)으로 묶음 |
| 대화 중 새 사람 합류(필재 미등록, 다니엘·강석 등록) | 필재 자기소개를 **"강석"으로 붙임** — 새 사람으로 알아보지 못함 |
| 이름 인식(등록 문장) | 기본 등록 문장(`reg_*`)의 다니엘·강석은 맞음. "필재" → "실제", "퓨제", "피 제이", "하야입니다" → 정규식이 "하", "다니엘이라고 합니다"(ash) → "한일", "강석이에요" → "간서디에요?" |
| 이름 추출 정규식 | 초안(`저는\s*(\S+?)\s*(입니다|…)`)은 "다니엘이라고 합니다"류에서 못 찾음. 개선안도 "하야입니다" → "하"(게으른 매칭과 `야` 어미), "제 이름은 피 제이에요" → "제". 둘 다 그대로는 못 쓴다 |
| 지연(4.3초 발화, 3회 중앙값) | diarize **3.45초** vs `gpt-transcribe` 0.79초(+2.7초) |
| 지연(12.4초 혼합, 3회 중앙값) | diarize 5.29초 vs `gpt-transcribe` 0.97초 |
| 본문 품질 | 거의 같음(띄어쓰기 차이 정도). known speaker 없을 때 "원 날씨", "글책" 같은 오인식 |

## 판단

- **미등록 소리를 버리지 못한다.** 등록 화자가 있으면 다른 목소리(성별이 달라도)를 가장 가까운 등록 화자에 붙이는 경향이 뚜렷하다. 요구의 핵심("TV·지나가는 사람은 버린다", "화자별 내용이 섞이지 않게")을 이 API만으로는 맞출 수 없다.
- 비슷한 목소리(남성 셋) 구분도 흔들린다. TTS 보이스는 실제 사람보다 서로 비슷할 수 있어 실제 사람 목소리로는 나아질 수 있지만, 성별이 다른 TV까지 등록 화자로 붙은 점은 목소리 차이 문제로 보기 어렵다.
- 지연이 턴마다 2.7초 이상 는다(NFR-01 이미 6.6초 미달).
- 이름은 음성 인식으로 받기 어렵다(흔치 않은 이름). 등록 때 화면에 이름을 입력하거나, 인식한 이름을 보여 주고 고치게 해야 한다.
- 제니를 known speaker로 넣으면 메아리는 걸러진다(참가자 3명 한도).

## 다음 방향 후보(사용자 결정)

1. **서버 화자 임베딩 검증(추천)**: 본문은 지금처럼 `gpt-transcribe`(빠름), 화자 판정은 서버에서 오픈 모델(ECAPA-TDNN·WeSpeaker 등 ONNX, CPU 수십~수백 ms)로 등록 임베딩과 유사도를 재 임계값 아래면 버린다. 한 발화 안에 여러 사람이 섞인 경우는 VAD 구간이 보통 한 사람이라 발화 단위 판정으로 시작하고, 필요하면 diarize로 구간을 나눈 뒤 구간마다 임베딩 검증. OpenAI만 쓰라는 지시와 다르다.
2. OpenAI diarize로 구간만 나누고 각 구간을 1의 임베딩으로 검증(정확도는 가장 좋을 수 있지만 지연 +2.7초).
3. OpenAI만 유지하고 실제 사람 목소리로 다시 재 보기(사용자가 몇 사람 녹음 제공). 미등록 거르기 실패는 그대로일 가능성이 크다.
